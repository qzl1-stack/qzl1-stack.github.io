#### 四种格式一览

|维度|Protobuf|FlatBuffers|MessagePack|自定义结构体|
|---|---|---|---|---|
|需要 Schema|✅ .proto|✅ .fbs|❌ 无需|❌ 手写头文件|
|包体大小|小|稍大|中|**最小**|
|反序列化|需复制到对象|**零拷贝**原地读|流式解析|**直接 cast 指针**|
|动态内存|需要|不需要|可选|不需要|
|随机字段访问|✗|✅ 偏移表|✗|手算偏移|
|向后兼容|⭐⭐⭐⭐⭐|⭐⭐⭐⭐|⭐⭐⭐|⭐|
|多语言支持|极广|较广|极广|仅 C/C++|
|嵌入式 C|nanopb|**原生支持**|mpack 库|**天然适配**|
|开发效率|高|中|**最高**|低|

#### 选型建议

**自定义结构体** — 双端纯 C、内存 KB 级、协议固定不变、极致性能优先。工控/嵌入式首选，你们 GCP 框架里的帧格式就是这条路。

**FlatBuffers** — 双端纯 C 但协议还会演进，或需要随机访问大消息中的某个字段而不想全量解析。IoT 上报大结构时合适。

**Protobuf** — 多语言端互通（设备 C + 后台 Go/Java/Python），接口迭代频繁，需要严格的 Schema 版本管理。gRPC 体系标配。

**MessagePack** — 原来用 JSON 嫌太大，想快速替换且不想写 Schema。消息结构灵活多变，快速原型阶段。

### 除二进制外，还有哪些数据格式？

数据格式按编码方式大致分为四类：

**文本类（人可读）**

- **JSON** — 最通用，Web API 事实标准，冗余大，解析慢
- **XML** — 更冗余，但命名空间和 Schema 验证完善，工控/电力（IEC 61968）常见
- **YAML** — 配置文件首选，比 JSON 更易读，不适合传输
- **TOML** — 比 YAML 简单，适合小型配置文件
- **CSV** — 纯表格数据，极简，无嵌套，报表/日志导出常用
- **INI** — 最简单的 key=value 配置格式，嵌入式设备配置常见

**二进制类（高效传输）**

- Protobuf / FlatBuffers / MessagePack / 自定义结构体（上面已详述）
- **CBOR** — 二进制版 JSON，IoT 领域标准（CoAP 协议配套）
- **Avro** — Hadoop 生态，Schema 随数据一起走
- **Parquet / ORC** — 列式存储，大数据分析专用，不用于传输

**描述类（结构定义）**

- **ASN.1** — 电信/金融领域，定义数据结构后可编码为 BER/DER/PER 等多种格式
- **IDL**（Interface Description Language）— 如 Thrift、Cap'n Proto 的 Schema 语言

**领域专用类**

- **Modbus RTU/TCP 帧** — 工控领域自定义二进制，你们最熟悉的
- **IEC 60870 / DNP3** — 电力规约，本质也是自定义二进制
- **HDF5** — 科学计算，存多维数组和元数据

---

**一句话总结：** 追求性能和体积用二进制；追求可读性和互操作用 JSON/XML；配置文件用 YAML/TOML/INI；大数据分析用 Parquet。
